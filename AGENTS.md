# AGENTS.md

NixOS flake-based homelab/dotfiles repository. Single machine config for the host `ankylo` (an HP laptop with NVIDIA graphics). No README exists; this file is the primary orientation.

## Essential commands

All commands run from the repo root. The repo defines no devShell, no formatter, no CI, and no tests — validation is manual.

```bash
# Build/rebuild the only host. Requires root (rebuild switch alters /etc).
sudo nixos-rebuild switch --flake .#ankylo

# Build without applying
nixos-rebuild build --flake .#ankylo

# Evaluate config (fast syntax check without building)
nix eval .#nixosConfigurations.ankylo.config.system.build.toplevel.drvPath

# Update all flake inputs (see homelab-secrets gotcha below)
nix flake update

# Update a single input, e.g. nvf
nix flake update nvf
```

`nixos-rebuild` runs on the machine itself; there is no `nix develop`, `nix fmt` (no formatter output), or CI pipeline.

## Architecture

### Flake entry — `flake.nix`

- Inputs: `nixpkgs` (`nixos-unstable`), `home-manager`, `disko`, `nvf` (Neovim), `sops-nix`, and **`homelab-secrets`** — a separate **private** repo fetched via `git+ssh://git@github.com/WardenDigital/homelab-secrets.git`.
- Outputs a single `nixosConfigurations.ankylo`. `homelab-secrets` is passed as `specialArgs` to the NixOS modules and to `home-manager.extraSpecialArgs`.
- Home-manager is wired as a NixOS module (not standalone): `home-manager.useGlobalPkgs = true`, `useUserPackages = true`, user `ankylo`, and `backupFileExtension = "hm-backup"` (conflicting dotfiles get a `.hm-backup` backup instead of failing).
- `system = "x86_64-linux"` only.

### Host layout — `hosts/ankylo/`

`configuration.nix` is the NixOS entry; it imports:

| Import | Purpose |
| --- | --- |
| `disko-configuration.nix` | Disk partitioning (module from `disko` input) |
| `hardware-configuration.nix` | Generated by `nixos-generate-config` — **do not modify** |
| `users/ankylo/ankylo.nix` | User account + services + docker wiring |
| `configurations/locale.nix` | TZ `Europe/Zagreb`, `en_US.UTF-8` default, Croatian LC_* extras |
| `configurations/laptop.nix` | Lid-switch ignore, TLP charge thresholds, `thermald`, `consoleblank=60` |
| `modules/packages/common.nix` | Shared `environment.systemPackages` |

`home.nix` is the home-manager entry (home.packages = chrome/chromium, git identity `homelab-ankylo` <homelab+wardendigital@proton.me>); it imports `home/cli.nix` (btop + yazi) and `home/terminal.nix` (collector that imports the shared terminal modules below).

`services/services.nix` is a collector importing `ssh.nix` (passwordless SSH, authorized key) and `sops.nix`.

### Shared modules — `modules/`

- `modules/packages/` — NixOS modules adding packages: `common.nix` (collector) → `cli.nix` (glibc, gcc, just, zoxide, fzf, fd, bat, ripgrep, yazi, jq/yq, etc.).
- `modules/home/terminal/` — **home-manager** modules, imported by hosts via `home/terminal.nix`:
  - `ghostty.nix` (runs `tmux` on launch, catppuccin-mocha theme)
  - `tmux.nix` (prefix Space, vi keys, `default-command "nu"`, catppuccin theme, sessionx/continuum/resurrect)
  - `nushell.nix` (large inline catppuccin theme in `configFile.text`, env PATH prepends, zoxide integration)
  - `starship.nix` (catppuccin_mocha palette)
  - `nvim/` — Neovim via **nvf** (see below)

### nvf (Neovim) — `modules/home/terminal/nvim/`

Configured through `programs.nvf.settings`. Split by concern; `nvim.nix` is the entry (imports `ui.nix`, `keybinds.nix`, `usercommands.nix`, `plugins/plugins.nix`):

- `ui.nix` — dashboard-nvim, noice, catppuccin theme (mocha, transparent), lualine
- `keybinds.nix` — leader keymaps
- `usercommands.nix` — raw `luaConfigPost` (yank highlight, `CpPath`/`CpFPath` commands)
- `plugins/plugins.nix` (collector) → `blink-cmp.nix` (autocomplete + snippets), `mini.nix` (mini.* suite + file explorer keymaps), `snacks.nix` (picker/dim/explorer/lazygit keymaps), `utils.nix` (flash.nvim)

Lua snippets are embedded with `lib.generators.mkLuaInline`. This is a niche nvf-ism — expect upstream nvf API churn when updating the `nvf` input.

### `common/dev/tools/docker.nix`

Unusual **curried function**: `{ active_user, ... }: { pkgs, config, ... }:` returns an actual module (the second lambda body is the module). Enables docker + podman, installs docker-compose/distrobox, adds `${active_user}` to the `docker` group. The **only** consumer is `hosts/ankylo/users/ankylo/ankylo.nix`, which calls it via:

```nix
(import ./../../../../common/dev/tools/docker.nix { active_user = "ankylo"; })
```

Note the "normal" form of that file is NOT how it's consumed — do not convert it to a plain module without updating the caller.

## Sevices: secrets (sops)

- `sops.nix` (imported) sets `sops.defaultSopsFile = "${homelab-secrets}/secrets/secrets.yaml"`.
- Age key auto-imported from `/etc/ssh/ssh_host_ed25519_key`.
- Secrets repo access requires SSH agent access to GitHub as `WardenDigital`. `nix flake update` will attempt to fetch it — expect failure on machines without that key.

## Known gotchas (verified)

- **`services/borg.nix` is dead code**: not imported by any collector or configuration module. It also contains placeholder values (`remotePath = "action-runner@<ip>"`) and plaintext sshKey/passphrase paths with `# switch to sops` comments. Don't assume it's active.
- **`hardware-configuration.nix`** is generated; hand edits get overwritten by `nixos-generate-config`.
- **`users/ankylo/ankylo.nix`** contains a committed `hashedPassword` (`$y$` = yescrypt). Don't touch it unless rotating the password.
- **disko disks** are hardcoded by-id: 120G WDC → `/` (vfat ESP 512M + ext4), 480G Kingston → `/data` (ext4, also created via a `systemd.tmpfiles` rule `d /data 0755 ankylo users -`). Any repartitioning must use these exact devices.
- **NixOS config**: `system.stateVersion = "25.11"` (also `home.stateVersion`). `nixpkgs.config.allowUnfree = true`; `nix-ld` enabled with a fixed library list; `trusted-users = ["root" "ankylo"]`; `xdg.portal.enable = false`.
- **Style conventions**: catppuccin mocha palette hex values are duplicated by hand in btop, tmux, nushell, starship, ghostty, nvim — keep them consistent when editing themes. Module-file style is `{ ... }: { ... }` one-liners for collectors; multi-line lambdas for real config. Top-level module files prefer `{ pkgs, ... }:` with `with pkgs;` inside lists. Four-space indent (the repo's nvim config also hardcodes tabstop/shiftwidth 4, expands tabs).
- Commits are terse single words (`upd`, `cleanup nvim`); recent branch tip. This project is actively early-stage.
